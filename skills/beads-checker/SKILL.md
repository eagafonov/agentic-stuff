# Beads Issue Checker

## Overview

Audit open beads issues against the current codebase to determine their resolution status. Inspects code on the current branch to verify whether reported bugs/tasks have been addressed, then reports findings and optionally closes resolved issues.

## When to Use

- Periodic issue hygiene — checking if open issues are stale
- After merging feature branches — verifying issues are resolved
- Before sprint planning — cleaning up the backlog

## Process

1. **List open issues**: `bd list --status=open -n 100`
2. **Show issue details**: `bd show <id>` for each issue to understand the reported problem
3. **Inspect codebase**: Use grep/read to check if the described bug or missing feature is still present
4. **Classify each issue** into one of three statuses:
   - ✅ **Fixed** — clear evidence the issue is resolved in the code
   - ❌ **Present** — the described problem still exists in the code
   - ⚠️ **Inconclusive** — code significantly changed, needs deeper inspection
5. **Report** findings as a summary table
6. **Ask user** which issues to close — never close automatically
7. **Close confirmed issues**: `bd close <id> --reason "<brief explanation>"`

## Classification Rules

- **Fixed**: The specific code pattern described in the issue has been replaced with the suggested fix or equivalent solution
- **Present**: The exact problematic code pattern described in the issue still exists at the referenced location
- **Inconclusive**: The referenced file/function no longer exists, was heavily refactored, or the issue references an unmerged MR

## NEVER

- Modify any source code
- Attempt to fix issues
- Close issues automatically — always ask user for confirmation first
- Mark as "Fixed" without verifying the specific code change

## Report Format

| Issue ID | Title | Status |
|----------|-------|--------|
| id-xxx | Short title | ✅ Fixed / ❌ Present / ⚠️ Inconclusive |

## Example Verification Patterns

- **Bug: wrong constant value** → grep the constant, check if value/comment matches
- **Bug: missing function call** → grep for the function in the expected location
- **Bug: race condition pattern** → check if atomic/locking construct was added
- **Feature request** → grep for the new function/endpoint/field
- **Config issue** → read the config file and check the value
